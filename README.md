# Alice in Cradle 联动（DGStudio 模块）

《爱丽丝的摇篮》（Alice in Cradle）× DGStudio 联动模块。游戏端模组（`AliceInCradleLink`，BepInEx 6 / Unity Mono 插件）读取 HP / MP / EP 等游戏数值并上报给 DGStudio；模组只做数据采集，模块也只登记变量——强度换算与设备动作全部在「事件流」画布里完成。模块依赖：无（仅 Python 标准库），游戏端模组及其全部依赖随模块自带。

## 功能

* 模组**按数据变动即时上报**命名通道（`HP`、`HPmax`、`MP`、`MPmax`、`EP`、`Hurt`、`Heal`、`MpLost`、`MpGain`、`Orgasm`、`Orgasming` 共 11 个，无变动不通信），本模块登记的游戏侧变量**就是这批通道**——它们各占「事件流」变量表「系统参数 · 不可改名」栏的一行，用 `{HP}`、`{HPmax}` 直接引用；
* `Hurt`/`Heal`/`MpLost`/`MpGain` 来自**游戏调用事件**，按**脉冲合并窗口**上报（时长可在模组配置「每单次伤害脉冲时间」调整）：首个事件立即开口输出并开启窗口；窗口内的新事件并入同一脉冲（不拆分输出）；窗口结束时一次性输出合并累计总量并归零——窗口内输出严格递增、窗口之间以 0 隔开；
* 血量清零后的 overkill 过量伤害、魔力槽空时的施放消耗，均按游戏显示数值上报；
* 设备读数（`StrengthA`、`StrengthB`、`Battery`、`Connected`、`Pressure`）也登记成「系统参数 · 不可改名」栏的五行，方向是**核心可写**：画布把值写进这些字段，模块按同名 HTTP 字段回传给游戏显示；**没接线的字段回传 0**，模块自己不采样设备读数。游戏内按 **F9** 开关 DGStudio 状态面板，面板显示回传字段与本地 HP / MP / EP、高潮计数等数值及上报状态；面板右上角的「折叠」把它收成一个小按钮（显示折叠与连接状态），再点一下还原，小按钮和面板标题栏都可以**按住拖动**改位置，拖到的位置会记住（写回配置的面板 X / Y），免得挡住游戏画面；
* 默认服务地址 `127.0.0.1:8920`。

## 在事件流里接线（设备动作的唯一入口）

模块不再内置「输入映射表 / 输出映射表」——设备只能由「事件流」的**写入卡片**驱动。把本模块的变量接进设备，在「事件流」页这样搭：

1. **输入页**打开右侧变量表的「系统参数 · 不可改名」栏，按住本模块变量行左侧的**拖动柄**拖到画布，即生成该变量的**读数卡**（如 `Alice · 当前生命`、`Alice · 本期掉血`，每拍输出当前值）；
2. 中间用公式 / 范围映射等卡片做换算，例如血量越低强度越高：`({HPmax} - {HP}) / {HPmax} * 200`；
3. 末端接**核心写入卡片**——设备动作一律写在**输入页**（这一页的数据流向是「模块 → 核心」），从卡片面板的「核心变量」分类取写入卡，如「郊狼通道 A 强度」「波形选择」「郊狼开火」「脉冲流频率 `in_pulse_a` / `in_pulse_b`」「急停（全部设备）」；触发时机用「值变动时」「周期更新」等驱动卡选择；
4. 想把设备状态回传游戏：接在**输出页**（这一页的数据流向是「核心 → 模块」）——从「核心读出」分类取读数卡（如 `COYOTE.StrengthA`、`COYOTE.Battery`），末端接本模块的**写入卡**（`Alice · 设备通道 A 强度` 等五行），写进来的值就按同名字段回传给游戏；不接线的字段回传 0。

急停等设备动作也一律走事件流；模块自己不再下发任何设备命令——宿主会拦下模块对设备输出的直写调用（日志记「已拦截模块直写设备输出」），只保留 `emergency_stop` 这类安全切断。

模块自带一份默认事件流「AliceInCradle」：输入页是血量 / 耗蓝驱动郊狼与 OVC 的接线，输出页就是上面第 4 步那五行回传连线，启用模块时自动登记为可选配置，在「事件流」页把当前配置切到它即可直接用；同名配置已被你自己改过时不会被覆盖。

## 安装

### 模块安装（DGStudio）

在 DGStudio「模块」页的在线列表中获取本模块，安装时优先合并仓库自带的依赖，卸载 / 更新即热重载生效。也可手动把本仓库 `modules/<模块 id>/` 文件夹整个放入应用目录的 `modules/` 下。

### 游戏模组安装

模块页提供**一键安装**：

1. 打开「模块」页，在「Alice in Cradle 联动」卡片的**游戏模组**行填入游戏根目录（含 BepInEx 的那一层），或点「自动扫描」搜索。
2. 点安装，模组会被释放到 `BepInEx/plugins/AliceInCradleLink/`。路径会被记住，之后可一键安装。
3. 启动游戏，到「事件流」页把模组上报的通道接进设备写入卡片（见上文「在事件流里接线」）。

目标目录**缺 BepInEx 时自动安装模块携带的 BepInEx 6（Unity Mono）发行包**再释放模组——只要选中的是游戏根目录（含游戏主程序 exe）即可，全程无需联网。

模组按 **BepInEx 6** 编译，只能被 6.x 加载器装载；仍停留在 BepInEx 5 的旧游戏版本请用模块的旧版发布，或按上面的自动安装换成 BepInEx 6。

## 配置与使用

DGStudio 侧（「模块」页）：

* 服务地址在模块卡片内配置（默认 `127.0.0.1:8920`）；
* 回传字段在每次 HTTP `/data` 拉取时按当前值现取现给，刷新节奏由游戏侧的「回传轮询间隔」决定；变量表里游戏通道变量的实时值随游戏上报即时更新；
* 换算与设备动作不在模块里配置——变量登记好之后，全部在「事件流」画布上用变量表的**读数卡** + 核心的**写入卡**接线；
* 旧版的「输入映射表 / 输出映射表」设置项已随模块直写设备一并取消，「设备读数采样间隔」也已随模块自动采样一并取消；装载时会自动清掉这些遗留数据并在日志里提示改到事件流接线。

游戏侧（BepInEx 配置，写入 `BepInEx/config/dev.dgstudio.alicein_cradle.link.cfg`）：

| 配置项 | 说明 |
| --- | --- |
| 启用联动 | 关闭后模组不再读取游戏状态，也不再与 DGStudio 通信。 |
| DGStudio 地址 | DGStudio「Alice in Cradle 联动」模块的数据服务地址，默认端口 8920。 |
| 每单次伤害脉冲时间 (秒) | 伤害/回血/耗蓝/回蓝脉冲的存续时长：首个事件立即输出并开启窗口；距上次输出小于该时长的新事件并入同一脉冲（只累计、不拆分输出），窗口结束时一次性输出合并累计总量并归零。设小则逐事件拆分，设大则持续伤害合并为持续脉冲。 |
| 回传轮询间隔 (秒) | 拉取设备回传字段的间隔。 |
| 单次变化生效上限 | 差分信号超过此值视为数据异常（读档/换场），不产生信号。 |
| 高潮状态保持 (毫秒) | `Orgasming` 信号在一次高潮后保持为 1 的时长。 |
| 显示/隐藏热键 | 切换 DGStudio 状态面板（默认 F9）。 |
| 默认显示 | 启动时是否显示面板。 |
| 面板 X / 面板 Y | 面板左上角横 / 纵坐标；游戏内拖动面板或小按钮时自动改写并记住。 |

## 常见问题

* **游戏更新后联动停了？** 模组启动时若发现玩家组件缺少 hp/maxhp/mp/maxmp/ep 字段，会记录「当前游戏版本可能与此模组不兼容，联动已停止」——需等待模组适配新版本。游戏版本不兼容导致事件钩子安装失败时，对应通道自动回退为逐帧差分，联动不中断。
* **状态面板不见了？** 游戏内按 F9 切换显示；若面板绘制异常，模组会自动关闭面板防止刷屏，并在日志记录错误。
* **模组装上没有日志？** 先看游戏 `BepInEx/LogOutput.log` 开头写的加载器版本——本模组按 BepInEx 6 编译，BepInEx 5 认不出它，日志里不会出现 AliceInCradleLink 任何一行。用模块页的一键安装重装一次加载器即可。
* **接线改了要重启吗？** 不需要，「事件流」画布与模块设置都是即时生效；只有服务地址 / 端口需要重新开关一次模块。
